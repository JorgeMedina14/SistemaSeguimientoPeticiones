================================================================================
  SISTEMA DE PETICIONES CIUDANANAS - MUNICIPALIDAD DE JALAPA
  GUIA DE PRUEBAS CON POSTMAN
================================================================================

Base URL (local):
  http://localhost:5000

Requisitos previos:
  1. SQL Server en ejecucion (instancia configurada en backend-muni\.env)
  2. Backend: cd backend-muni  ->  npm start
  3. Postman instalado

================================================================================
  CONFIGURACION EN POSTMAN
================================================================================

1) Crear un Environment (opcional pero recomendado):
   Variable          | Valor inicial
   ------------------|------------------
   base_url          | http://localhost:5000
   token             | (dejar vacio; se llena tras login)

2) Headers comunes (para rutas protegidas):
   Content-Type: application/json
   Authorization: Bearer {{token}}

   En Postman: pestana Authorization -> Type: Bearer Token -> Token: pegar el JWT

3) Obtener el token (SIEMPRE PRIMERO):
   POST {{base_url}}/auth/login
   Body raw JSON (ver seccion AUTH abajo)
   Copiar de la respuesta: data.token

================================================================================
  USUARIOS DE PRUEBA
================================================================================

  Usuario      | Password      | Rol
  -------------|---------------|-------------
  admin        | admin123      | ADMIN
  alcalde      | alcalde123    | ALCALDE

        Usar admin para crear usuarios JEFE_DEPTO si hace falta.

================================================================================
  VALORES VALIDOS EN EL SISTEMA
================================================================================

  Estados de peticion:
    RECIBIDA, EN_REVISION, ASIGNADA, EN_PROCESO, RESUELTA, RECHAZADA, CERRADA

  Prioridades:
    BAJA, MEDIA, ALTA

  Roles de usuario:
    ADMIN, ALCALDE, JEFE_DEPTO, RECEPCION

  DPI ciudadano:
    Exactamente 13 digitos numericos (ej: 1234567890101)

================================================================================
  ORDEN SUGERIDO DE PRUEBAS (SCRIPT)
================================================================================

  Paso 1:  GET  /health
  Paso 2:  GET  /db/ping
  Paso 3:  POST /auth/login  (usuario: admin)
  Paso 4:  GET  /auth/me
  Paso 5:  GET  /departamentos
  Paso 6:  POST /peticiones  (usuario: recepcion o alcalde)

  Paso 10: GET  /reportes/dashboard
  Paso 11: GET  /usuarios  (solo admin)
  Paso 12: DELETE /peticiones/:id  (admin o alcalde, opcional)

================================================================================
  SCRIPTS POSTMAN (Tests tab) - Opcional
================================================================================

  En la peticion POST /auth/login, pestana Tests, pegar:

  ---
  if (pm.response.code === 200) {
      var json = pm.response.json();
      if (json.data && json.data.token) {
          pm.environment.set("token", json.data.token);
          console.log("Token guardado en variable 'token'");
      }
  }
  ---

  Luego en otras peticiones usar Authorization: Bearer {{token}}

================================================================================
  ERRORES COMUNES
================================================================================

  401 Unauthorized
    - Falta header Authorization
    - Token expirado (volver a hacer login; dura 8h por defecto)

  403 Forbidden
    - El rol del usuario no tiene permiso para esa ruta
    - Ej: recepcion no puede acceder a /usuarios

  400 Bad Request
    - DPI distinto de 13 digitos
    - estadoNuevo invalido
    - Campos requeridos faltantes

  404 Not Found
    - id de peticion o usuario no existe

  Error de conexion / ECONNREFUSED
    - Backend no esta corriendo en puerto 5000

  Error SQL Server
    - Instancia apagada o credenciales incorrectas en .env
    - Probar GET /db/ping
